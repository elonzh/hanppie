# 官方 App 能力对照与实施状态

> [文档导航](../../README.md) / [官方 App 对照](README.md)

## 目标与范围

本表维护官方 App 能力补齐的任务范围、包状态、保留决策和待验事项。阅读当前产品实现先看 [Hanppie 技术架构](../../architecture/hanppie.md)，原机机制与指令以 [RoboMaster 架构与协议](../../architecture/robomaster.md) 为准。

多机对战暂缓，官方 GamePad 不纳入；鼠标云台已移除，界面仅维护中英文。各项处理仍以下方实施清单和排除表为准。离线交付与真实设备验收分别认定，不用任务包数量表示官方等价率。

近期实机结果见 [S1 实机验证](../../records/device/s1-live-validation-2026-10-25.md)，设置与媒体改进见 [媒体与状态评审](../../records/ui/ui-media-status-review-2026-10-26.md)。历次范围调整、逐阶段提交和测试输出已移入 [实施与验证记录](../../records/official-app/implementation.md#提交与验证记录)，固定基线的复核见 [历史复核索引](../../records/official-app/README.md)。

## 阅读顺序

1. 在 [实施清单](#实施清单) 找到用户任务，点击任务编号查看当时的提交、测试与待验项。
2. 涉及行为差异时查看 [保留决策](#冲突记录保持现状留待决策)。
3. 判断当前产品能力回到 [架构能力矩阵](../../architecture/hanppie.md#110-当前能力矩阵)，设备效果核对 [实机记录](../../records/README.md#实机与原机调查)。

## 状态与验收

| 状态 | 含义 |
| --- | --- |
| 待实施 | 尚未开始，保留全部原始范围 |
| 实施中 | 正在补协议证据、实现或验证，不表示完成 |
| 离线完成 | 代码、桌面入口、必要离线验证和提交完成；对应物理验证仍待进行 |
| 冲突待决策 | 与现有功能冲突；本轮保持现状，见后文决策依据 |
| 用户暂缓 | 用户明确移出本轮实现与验收；保留记录，不计作已完成，未经重新纳入不继续推进 |
| 不纳入 | 用户排除，或仅内部/条件能力而非已确认用户任务 |

每项离线完成时记录提交、验证命令/结果、证据位置和设备待验内容。每个新设备功能至少验证正确报文、错误/超时、断连清理与状态归属；有持续动作时增加停止、失焦和不自动恢复验证。有 UI 的功能在桌面按横屏紧凑/中等/宽窗口验收，不以构建代替界面验证。
