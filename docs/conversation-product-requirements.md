> 范围：Android 与桌面 KMP 客户端的对话体验

## 1. 产品目标

这一阶段不是扩展更多机器人技能，而是让用户可以可靠地配置模型、验证模型、管理对话，并始终知道智能体正在做什么、是否完成以及中断后能否安全继续。

产品体验只消费运行时的稳定状态，不自行判断 provider 事件、工具是否完成或历史是否可恢复。

### 1.1 实现状态

已实现四个指定供应商与 Custom、预设/发现/手动模型选择、四阶段配置测试、持久对话的基本管理、按 Agent Session 隔离的内存草稿、窄屏/宽屏布局、桌面核心快捷键以及回复朗读移除。当前运行过程可见思考、流式文本、语法高亮代码、审批、工具记录、取消和失败；智能体可查询已核对的 Lab API，并以名称展示脚本列表，按稳定 ID 读取、更新、重命名和经确认后删除用户脚本。包含用户 `Message.User` 的 `AgentStartingEvent` 写入 JSONL 后才清空草稿，重启会把未结束的 agent run 标记为失败，并把已开始但没有对应 `MessagePart.Tool.Result` 的工具标记为“结果未知”，不会重放工具。

尚未完成的增强项是：每供应商独立保存 profile/key、推荐/最近模型分组、能力来源与三态证据、待审批卡片跨重启恢复、“结果未知”的结构化详情卡、分页以及 P1 搜索/诊断/导出。它们保留在本文作为后续验收范围，不能解读为当前产品事实。

## 3. 模型服务体验

### 3.1 供应商选择

设置页的“模型服务”使用供应商卡片或下拉选择，不要求用户先理解 endpoint：

- DashScope；
- OpenAI；
- DeepSeek；
- MiMo；
- Custom。

首批预设如下；内置目录按 Hanppie 版本维护，服务端地址仍以供应商当前官方文档和用户套餐为准：

| 供应商 | 默认推理地址 | 模型发现 | 当前协议策略 |
| --- | --- | --- | --- |
| DashScope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 独立 `https://dashscope.aliyuncs.com/api/v1/models`，专属工作空间可覆盖 | OpenAI-compatible Chat Completions |
| OpenAI | `https://api.openai.com/v1` | `{baseUrl}/models` | Chat Completions |
| DeepSeek | `https://api.deepseek.com/v1` | `{baseUrl}/models` | Chat Completions；历史与上下文由本地运行时管理 |
| MiMo | `https://api.xiaomimimo.com/v1` | `{baseUrl}/models` | Chat Completions；历史与上下文由本地运行时管理 |
| Custom | 用户输入 | 尝试 `{baseUrl}/models` | OpenAI-compatible Chat Completions，不自动回退 |

地址与兼容范围参考供应商当前官方说明：[DashScope base URL](https://help.aliyun.com/en/model-studio/base-url) · [OpenAI Chat Completions](https://platform.openai.com/docs/api-reference/chat/create) · [DeepSeek API](https://api-docs.deepseek.com/) · [MiMo 快速开始](https://mimo.mi.com/docs/zh-CN/quick-start/summary/first-api-call)

选择预设后自动填入标准 endpoint 和模型；endpoint 与模型 ID 仍可直接编辑，以支持地域/工作空间地址和专属部署。当前不提供协议切换，所有供应商显式走 Chat Completions；以后引入 Responses 必须作为 provider profile 能力演进，不能静默切换已有配置。DashScope 工作空间域名、MiMo Token Plan 等专属地址允许覆盖，但不得根据 key 类型猜测或静默替换。

每个供应商保存自己的 API Key、endpoint 和最近模型；来回切换供应商不需要重复输入。API Key 默认遮挡，支持替换和明确清除，不提供复制按钮。

### 3.2 模型选择器

打开设置页或切换供应商不请求远端模型目录。只有用户展开模型选择器时才按当前供应商、endpoint 和 API Key 发起一次目录请求；内置推荐项与当前模型立即可选，远端结果返回后再补入同一个列表。没有 API Key 时不联网，只提示可在填写后获取；失败不自动重试，也不阻止手动输入，用户再次展开选择器即明确触发刷新。

模型选择器分为：

1. **推荐**：Hanppie 内置目录中确认支持文本、流式和工具调用的常用模型；
2. **最近使用**：该供应商最近成功使用的模型；
3. **全部可用**：供应商发现返回的模型；
4. **手动输入**：目录不可用、专属部署或新模型使用。

每项最多展示：

- 模型显示名与准确 ID；
- 输入模态；
- 上下文与最大输出；
- 工具调用、流式、推理与结构化输出能力；
- 信息来源：供应商发现、Hanppie 预设、实际测试或手工覆盖；
- 上次验证时间。

能力未知的模型不能伪装为不支持，也不能静默隐藏。用户仍可选择，但发送前显示“尚未验证工具调用”的提示。

### 3.3 配置编辑与测试

编辑使用草稿，只有“保存”才替换当前有效配置。“测试”使用草稿，不要求先保存；失败后继续沿用原配置。

测试结果按步骤展示：

| 步骤 | 成功含义 | 不能证明 |
| --- | --- | --- |
| 本地校验 | 地址、key、模型字段格式可用 | 网络与鉴权 |
| 目录 | key 可以访问目录、模型可见 | 模型推理可用 |
| 流式文本 | 目标模型返回完整流式终态 | 工具调用可用 |
| 工具探测 | 无副作用 echo 工具参数可往返 | 机器人动作已执行 |

结果使用“通过 / 失败 / 跳过 / 未确认”，显示耗时和可操作建议。不得显示 API Key、Authorization、完整 provider 错误 body 或用户其他对话内容。

流式文本与工具探测会各发出一个受限的真实请求，可能产生少量供应商费用；测试前应明确提示，限制最大输出，并且只注册无副作用的 echo 工具。

设置在智能体运行中可编辑和测试，但保存的新模型只影响下一次 agent run；当前 run 始终显示其启动时的模型快照。

## 4. 对话列表与管理

### 4.1 列表项目

每个对话显示：

- 标题；
- 最近一条可见内容的短预览；
- 最近活动时间；
- 当前状态标识：运行中、待确认、需要处理或普通；
- 最近使用的供应商/模型，仅在详情中完整展示，列表保持克制。

默认按 `recencyAt` 倒序。运行中、待审批或结果未知的对话不能因为旧 `updatedAt` 被埋没。

### 4.2 管理动作

- **新建**：立即创建空白对话并聚焦输入；空白且从未发送的对话离开后不保留；
- **重命名**：首条用户消息生成本地默认标题，用户修改后不再自动覆盖；
- **搜索**：P1 先搜索标题与 SQLite 投影中的可见文本，不扫描所有 JSONL；
- **永久删除**：二次确认，明确会删除对话事件与附件且不可恢复。待审批、运行中或结果未知的对话必须先结束/处理，不能直接删除。

不在第一阶段加入 pin、文件夹、标签或批量管理；这些能力移除后不会影响当前核心任务，暂不引入。

### 4.3 打开与切换

- 打开历史对话时从 SQLite 分页加载稳定的 Koog `Message` 投影；
- 活动流式内容由运行时实时状态补在列表尾，不伪装为已完成消息；
- 切换到其他页面或对话不取消当前 agent run；
- 第一阶段应用只允许一个活动 agent run 使用机器人工具。其他对话仍可浏览和编辑草稿，但发送时明确提示当前占用者；
- 重启后自动打开最近对话。当前会安全拒绝未决定审批并显示中断提示；已开始工具则显示结果未知。恢复原审批卡片属于后续增强。

## 5. 对话页

### 5.1 消息与工具内容展示

不要继续把所有内容映射为 `role + text`。UI 至少区分：

- 用户消息；
- assistant 最终回复；
- 流式临时回复；
- 可折叠的工具调用与结果；
- 脚本审批卡片；
- 中断、失败、截断与结果未知提示；
- 模型/上下文迁移提示。

运行时原始事件默认不直接展示；从“运行详情”进入诊断视图或导出。当前未发布格式不做未知事件兼容；事件或 Koog `MessagePart` 无法解析时明确报告持久化错误，不伪造可继续使用的历史。

用户消息使用靠右、随内容收缩且限制最大宽度的克制容器，短消息不得被拉成长条；assistant 输出在主内容区直接排版，不使用聊天气泡，也不显示“我”或智能体名称。工具、脚本与系统状态按自身语义显示，不伪装成 assistant 对话。

工具调用使用紧凑的工具活动行，按状态、API 查询、脚本读取、保存、删除、执行和停止显示对应名称、图标、结构化摘要与阶段。参数和结果按对象字段、数组项和标量分组，源码字段使用 Python 代码块；完整详情默认折叠，用户主动展开时才显示。失败行可以直接显示一条受限摘要并保留详情入口。界面不得把参数 JSON 或 Tool Result 当成一整段字符串倾倒，也不得把工具结果再次作为 assistant 消息重复展示。

assistant 回复与脚本审批中的 fenced code 必须按语言标识进行语法高亮；未标语言的代码仍按等宽代码块呈现。高亮只改善展示，不改写源码，也不影响事件中保存的 Koog `Message` 或工具参数。

打开 Session 或用户消息成功发送后，消息区定位到列表底部；当前回复持续生成且用户仍在查看末尾时，视口随内容增长保持在最新位置。用户主动向上滚动后暂停自动跟随，回到底部或再次发送消息时恢复。

### 5.2 输入与发送

- 输入草稿按 `sessionId` 保存在 UI 状态，切换对话不互相覆盖；
- 发送后只有包含用户 `Message.User` 的 `AgentStartingEvent` 已持久化才清空输入框；
- 输入支持多行、粘贴与系统输入法；IME 正在组词时 Enter 不能被抢作发送；
- `Enter` 发送，`Shift+Enter` 换行；点击发送按钮与键盘发送必须进入同一个提交路径；
- 没有有效模型配置时，发送按钮跳转到模型服务设置并保留草稿；
- 达到上下文预算时解释原因并提供“新建对话”，不静默截断；
- 网络失败后“重试”必须标明只重试模型请求。出现已开始或结果未知的副作用工具时不提供整个 agent run 的一键重试。

### 5.3 运行反馈

运行状态使用用户能理解的阶段：

- 正在连接模型；
- 正在生成；
- 等待确认；
- 正在执行脚本；
- 正在整理结果；
- 已取消；
- 请求失败；
- 执行结果未知，需要检查机器人状态。

工具卡片必须区分“准备执行”“已批准”“命令已发送”“明确完成”和“结果未知”。模型文字不能覆盖工具的真实状态。

脚本审批通过即完成本次人工确认，发送启动命令后不得再次提示用户确认。“等待机内脚本启动”只表示尚未收到匹配的 `STARTED` 回报；超过有限等待时间必须转为“结果未知”并提供检查/停止入口，不能永久显示加载状态，也不能自动覆盖或重跑脚本。

取消按钮只取消当前 agent run。涉及机器人时持续保留现有提示：取消对话不等于停止机器人脚本；停止脚本必须调用专门入口。

## 6. 自适应布局

### 6.1 桌面与宽屏

- 左侧常驻对话栏占满对话页可用高度，主区域显示当前对话；记录列表在侧栏内独立滚动，不能随记录数量改变侧栏高度；
- “新对话”放在对话栏标题区，不作为脱离列表的主内容悬浮操作；
- 列表支持键盘导航和搜索；
- 工具详情可以在当前消息内折叠，不增加第三个常驻面板；
- 设置从现有工作台导航进入，不把供应商配置塞进对话栏。

### 6.2 手机与窄屏

- 对话页保持单栏；历史列表从顶栏进入弹层，列表随内容收紧并在标题区提供“新对话”；
- 返回键先关闭弹层/审批详情，再返回列表，不取消运行；
- 所有点击目标保持至少 48dp；
- 工具参数、脚本与错误正文可横向滚动或换行，不能挤压主操作按钮。

## 7. 桌面快捷键

`Mod` 在 macOS 为 `⌘`，Windows/Linux 为 `Ctrl`。快捷键只在对话相关 route 生效，不能抢占驾驶舱的 WASD、方向键、空格、数字键和 Esc。

| 快捷键 | 动作 | 约束 |
| --- | --- | --- |
| `Mod+N` | 新建对话 | 不取消当前运行；打开新空白对话 |
| `Mod+B` | 打开或关闭窄屏对话记录 | 宽屏已常驻显示侧栏 |
| `Mod+L` | 聚焦输入框 | 不修改现有草稿 |
| `Mod+,` | 打开设置 | 保留当前输入草稿 |
| `Enter` | 发送 | IME 正在组词时不拦截 |
| `Shift+Enter` | 换行 | 所有桌面平台一致 |
| `Esc` | 取消当前 agent run | 有弹层时先关闭弹层；无运行时不清空草稿 |

审批卡片的“同意并执行”不提供单键快捷键，避免误触发机器人动作。拒绝可以通过聚焦按钮后正常确认，Esc 只取消当前 agent run，不等同于同意或执行。

## 8. 移除回复朗读

本需求只移除 KMP 客户端对 assistant 文字的 TTS 朗读：

- 删除回复旁“朗读”、全局“停止朗读”和“自动朗读”；
- 删除设置中的自动朗读开关及 Android 系统 TTS 设置入口；
- 删除 `SpeechEngine`、`ReplySpeaker`、`AndroidSpeech`、`SystemSpeech` 及只服务于它们的测试、资源和 Android TTS service query；
- 从新设置 schema 删除 `autoRead`，迁移旧 DataStore 时明确丢弃该字段，不因旧字段导致整个设置加载失败。

以下能力不在本次移除范围：

- Android 系统语音识别输入及其服务选择；
- 机器人麦克风、扬声器、远程对讲和媒体播放；
- Python `hanppie agent` 的独立语音交互与 TTS。其当前能力和验证边界仍由技术架构维护。

## 9. 历史与诊断体验

普通用户看到 SQLite 投影。诊断入口可以：

- 查看 Session ID、Koog run ID、模型快照、token 用量和阶段耗时；
- 查看完整异常、traceback 与供应商 request ID；
- 导出单个对话的 `events.jsonl` 与附件；
- 在投影损坏时触发“从原始记录重建索引”。

导出前提示事件可能包含用户对话、模型输出、生成脚本、工具结果和相机附件。默认不导出其他对话、API Key、HTTP headers 或应用全局设置。

## 10. 分阶段验收标准

标为“已实现”的条目属于当前基础切片；标为“后续”的条目只有在相应增强里程碑完成后才可用于宣称交付。

### 10.1 模型配置

- **已实现：** 四个预设和 Custom 均可选择；远端目录只在展开模型选择器时按需获取，目录失败时仍可手动输入模型；
- **已实现：** 测试四阶段各自有结果，不把 `/models` 成功显示为“智能体可用”；
- **已实现：** 保存失败不覆盖上一个有效配置；
- **后续：** 切换供应商时各自 profile/key 不串，能力来源与未知状态以三态证据展示。

### 10.2 对话

- **已实现：** 冷启动后对话列表、标题、已知消息顺序正确；
- **已实现：** 新建、重命名和永久删除符合定义；列表动作收纳在单个紧凑菜单中；
- **已实现：** 已开始但未完成的工具显示结果未知且不会重跑，未知 v1 事件不阻塞后续已知内容；
- **后续：** 搜索、分页、结构化状态卡以及待审批跨重启继续决定。

### 10.3 桌面与手机

- **已实现：** `Enter`、`Shift+Enter`、`Mod+N/B/L/,` 与 `Esc` 只挂载在对话页；快捷键说明只在设置的快捷键分组展示；
- **已实现：** 手机对话列表和桌面宽屏侧栏完成自适应渲染检查；
- **后续：** macOS 实际 `⌘`、Windows/Linux 桌面和复杂输入法组词行为做平台验收。

### 10.4 朗读移除

- Android 与桌面不再显示或初始化回复 TTS；
- Android manifest 不再查询 TTS service；
- 旧设置含 `autoRead=true` 时仍能迁移并正常打开；
- 语音输入、机器人对讲和 Python 语音智能体的相关测试不受影响。
