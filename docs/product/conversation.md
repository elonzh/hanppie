# Hanppie 对话体验

> [文档导航](../README.md)

本文维护模型设置、对话管理和交互的产品要求。实现与验证范围见[技术架构](../architecture/hanppie.md)；工具策略见[智能体产品设计](agent.md)，存储契约见[运行时设计](../architecture/agent-runtime.md)。

## 模型设置

供应商预设负责填入地址和模型，用户仍可修改 endpoint、模型 ID 和 API Key。密钥默认遮挡，保存在应用私有数据中，不进入日志、诊断和对话历史。

模型目录只在展开选择器或明确测试配置时请求。内置预设与当前模型先显示；目录失败不自动重试，用户仍可手动输入。编辑使用草稿，测试不要求先保存；保存失败不能覆盖有效配置，保存的新模型只影响下一次运行。

配置测试分别报告本地校验、模型目录、流式文本和无副作用工具调用的结果、耗时与恢复建议。目录可访问不代表推理可用，文本成功不代表工具调用可用；模型请求可能产生费用，测试前说明。

## 对话管理

每条对话对应一个 Agent Session，按最近活动排序。列表显示标题、内容预览、时间和必要状态；模型详情放在详情页，运行中或需要处理的对话不能被埋没。

- 新建后聚焦输入，草稿按 Session 隔离。
- 默认标题来自首条用户消息，用户改名后不再覆盖。
- 永久删除需要确认，说明不可恢复；活动运行必须先结束。
- 切换页面或对话不取消运行。其他对话可浏览、编辑草稿，机器人任务占用时明确提示。
- 接受用户消息的耐久事件写入成功后才清空草稿。

重启后的中断处理以运行时为准，界面不能自行重放工具、补写成功结果或把未决定的审批恢复成已同意。

## 消息与运行反馈

用户消息靠右、随内容收缩并限制宽度；助手输出直接排版。工具活动、审批和系统提示分别展示，不伪装成助手消息。代码按语言高亮，展示不改写源码。

工具活动行显示用途、状态和简短结果，完整参数默认折叠。对象、数组和源码按结构展示，不倾倒整段 JSON，也不重复显示同一工具结果。持久化内容无法解析时明确报告错误，不伪造历史。

反馈应能区分生成中、等待确认、执行中、已取消、失败和结果未知。审批完成后不再次要求确认；启动回报超时必须结束等待并保留检查、停止入口。工具命令发送、协议确认、遥测变化与物理效果分别表达。

取消生成只取消当前 agent run。已经启动的机内脚本必须通过“停止脚本”停止；这两个动作在界面中分别保留。

## 输入与布局

输入支持多行、粘贴和系统输入法。没有模型配置时，引导到设置并保留草稿。上下文超限时解释原因并提供新对话入口，不静默截断；已开始副作用工具的任务不提供整体重试。

宽屏显示常驻对话侧栏，列表独立滚动；窄屏从顶栏打开对话记录，在列表标题区提供新建操作。工具详情就地展开，源码和错误正文不得挤压主操作。布局遵循 [DESIGN.md](../../DESIGN.md#布局与自适应)。

打开历史或发送成功后定位到末尾。用户仍在末尾时跟随流式输出；主动上滚后暂停跟随，回到底部或再次发送时恢复。

## 快捷键与语音

`Mod` 在 macOS 为 `⌘`，Windows/Linux 为 `Ctrl`。这些快捷键只在对话页生效，完整说明集中在设置中。

| 快捷键 | 动作 |
| --- | --- |
| `Mod+N` | 新建对话，不取消活动运行 |
| `Mod+B` | 开关窄屏对话记录 |
| `Mod+L` | 聚焦输入 |
| `Mod+,` | 打开设置，保留草稿 |
| `Enter` / `Shift+Enter` | 发送 / 换行；输入法组词时不抢占 Enter |
| `Esc` | 先关闭弹层，再取消当前 agent run；不清空草稿 |

批准执行不提供单键快捷键。语音输入先回填草稿，由用户检查后发送；系统识别服务可能联网。回复朗读不属于客户端交互，机器人音视频与对讲是独立能力。

## 扩展需求

供应商独立配置、能力来源与未知状态、最近模型、历史搜索/分页、审批跨重启恢复和诊断导出属于扩展需求，实现范围查技术架构。引入前需证明其对具体任务有帮助，不预置云同步、多用户、文件夹或多智能体。

诊断导出只包含选定 Session。导出前说明记录可能包含对话、脚本、工具结果与附件，不包含 API Key、HTTP headers、其他 Session 或应用全局设置。

## 验收要点

模型目录失败仍可输入；配置保存失败保留旧值；消息落盘失败保留草稿；对话切换不丢草稿。取消、断网和重启不会重跑机器人副作用；未知结果有恢复入口。窄屏、宽屏、键盘与输入法分别验证，模型测试和实机动作分别记录证据。
