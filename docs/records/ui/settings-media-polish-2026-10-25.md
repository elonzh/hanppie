本轮于 2026-10-25 开始，最终复核于 2026-10-26 完成，依据用户反馈调整菜单稳定性、媒体库导航与元数据、SD 预览、操作文案和设备信息。当前用法与职责见 README 和[架构说明](../../architecture/hanppie.md)；本文件只保留本次证据与边界。

## 实现与信息来源

- 设置分类摘要固定两行，选中前后保留箭头占位；设置任务行也限制摘要行数。设备信息并入机器人状态，基本信息与组件版本分组，宽度足够时按两列分配空间。未报告的里程、驾驶时长不再永久显示等待；失败的组件版本不作为“无数据”项目平铺。
- 媒体库成为应用导航的独立目的地，设置目录移除重复入口，SD 拍录与存储详情保留上下文入口。本地文件显示实际文件名、文件系统创建时间；创建时间缺失不以下载时间替代。SD 创建时间使用相机日历字段，不假设时区或校正设备时钟。
- SD 列表记录偏移 0 的 FAT 时间与此前真实 JPEG 的 EXIF 时间逐字段一致，已据此接入解析。非法日期保留未知，不丢弃整个文件列表。[DJI 官方文件结构](https://github.com/dji-sdk/Onboard-SDK/blob/master/osdk-core/modules/inc/filemgr/impl/dji_file_mgr_internal_define.hpp)提供相同字段定义。
- 录像预览不能直接当图片解码：本批真实返回为 160×120 NV16，共 38,400 字节；共享媒体域完成 BT.601 有限范围转换，不新增依赖或平台分支。照片仍使用编码图片解码。未知布局或被拒绝的预览转为下载入口，不提供重复无效的重试；传输故障仍可重试，已下载照片直接用于预览。
- 标题反馈、预览区域、列表图标和操作区保留稳定空间，操作使用“下载”“删除”等常规名称。两种媒体来源分别持有列表滚动位置，从远端打开已下载录像时显露对应本地项。

## 桌面与实机证据

桌面验证覆盖中英文、844×390、1024×600、1280×720 和 1.4 倍字体。设置/状态/媒体影响面 48 项复核通过；媒体与本地化 32 项、相册协议/会话 10 项通过；NV16 与相关流程 19 项及单独的录像预览界面验证通过。这些批次有重叠，不相加为唯一测试数量。首轮修正旧入口/连接身份断言与大字照片裁切；后续实际窗口发现分列取整和跨来源滚动问题，最终针对性两项复核通过。滚动用例按保留本地可见锚点校正断言，未要求插入新文件时挤走原阅读位置。

用户重启前，相册请求有设备应答但不返回列表；更换传输编号和关闭视频流未使其恢复。重启后，同一生产会话读取到该卡 **10 个条目**，**1 张 JPEG 照片预览、9 张 NV16 录像预览全部完成传输和生产解码**。共享 NV16 输出与 FFmpeg 对相同数据的结果比较，RGB 各通道平均绝对差分别约 1.62、1.15、0.85，均在 0–255 范围内。

当前原生应用沿首页 → 设置 → 导航媒体库 → 机器人 SD 卡验证实际照片与新旧录像预览，随后下载最新录像 **6,522,596 字节**；其 SHA-256 与此前完整原件一致，已在媒体库内部打开并播放画面。本轮下载副本保留在应用本地媒体库，便于用户继续查看。实际机器人状态页自动读到型号、激活和主固件；奇数像素宽度下分列及列表位置的最终修正由几何断言复核。

最终 `:desktopApp:createDistributable` 通过，包内共享模块与当前构建逐条一致。中英文资源各 1,878 项，无重复键；日志、阶段 XML、界面渲染与包身份位于忽略目录 `.hanppie/validation/2026-10-25-media-polish/`。原生截图由本次 CUA 返回，未复制进仓库。验证进程、FFmpeg 与应用会话均已关闭。

## 边界

- 本卡列表不含原始文件名扩展。官方 SDK 存在多种相机命名规则，其默认索引换算不能直接用于本次 S1 文件；远端仍使用编号标识，下载后显示本机真实文件名，不伪造 SD 原名。[官方命名实现](https://github.com/dji-sdk/Onboard-SDK/blob/master/osdk-core/modules/src/filemgr/impl/dji_file_mgr_impl.cpp)
- 重启前设备不返回列表的成因仍未建立独立复现。本轮未增加设备自动重启或未经确认的传输取消命令；预览格式问题的修复不等于所有相机故障都能自动恢复。
- 结论限定本次存储卡与已确认的预览布局；其他格式、故障注入、移动端运行和声音听感仍待验。未进行驾驶、发射、格式化、固件更新或 Android 验证；未提交或推送代码。
