## 状态与验收

| 状态 | 含义 |
| --- | --- |
| 待实施 | 尚未开始，保留全部原始范围 |
| 实施中 | 正在补协议证据、实现或验证，不表示完成 |
| 离线完成 | 代码、桌面入口、必要离线验证和提交完成；对应物理验证仍待进行 |
| 冲突待决策 | 与现有功能冲突；本轮保持现状，见后文决策依据 |
| 不纳入 | 用户排除，或仅内部/条件能力而非已确认用户任务 |

每项离线完成时记录提交、验证命令/结果、证据位置和设备待验内容。每个新设备功能至少验证正确报文、错误/超时、断连清理与状态归属；有持续动作时增加停止、失焦和不自动恢复验证。有 UI 的功能在桌面按横屏紧凑/中等/宽窗口验收，不以构建代替界面验证。

五种流程分别交付：

- 车轮先确认四轮可靠架空，按右前/左前/左后/右后手动转轮并等待进度；完整报告后显式进入轮位核对，只有按住才测试。触摸、空格/回车释放和失焦停止请求；无障碍激活为明确的有界脉冲。人工确认实际转动轮位与命令发送分别记录。
- 底盘装甲按后/前/左/右引导；事件去重、跳过前确认，跳过与敲击竞态进入未确认状态。已跳过步骤单独统计，不当成物理编号正确。
- 舵机分配 1–3、ToF 分配 1–4；先等待本轮静默，再逐个接入，保护初始占号、机械臂保留号和本轮已写编号。写号确认绑定候选编号，候选变化立即失效，服务执行前再检查。机械臂占号未知时拒绝开始并给出原因。工作模块报告不能证明没有物理重号。
- 舵机/ToF 结束编号后等待新的工作模块报告，再逐个识别灯与人工核对；结束 ACK 前已收到的本轮新报告保留，不沿用旧在线列表。识别灯约 3 秒后请求同色常亮，人工核对不从 ACK 推断，观察到离线时清除对应确认。
- 传感器转接板按官方板载按钮约 3 秒进入、按键循环、停止约 5 秒保存，提供 1–6 编号的四灯组合、在线编号与人工确认。没有制造远程写号命令；关闭引导不撤销硬件设置，因此不增加无实际作用的结束确认。

车轮动作由会话 tick、250 ms 租约、独立单次 1 秒期限与 500 ms 新鲜度约束；松开、失焦、超时、结束与关闭均尝试自身 CAN 节点归零。新按压不受旧零速补发覆盖；结束 ACK 后也不保留会干扰下一位控制者的补发。主机期限不能证明物理失联停止效果。
